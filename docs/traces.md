# Traces architecture and rollout

## Vertical slice

An agent command hook emits its native JSON to `scripts/submit-hook.ts`. The bridge adds source, event ID, session ID, event name and receipt time; it never edits the native payload. `POST /api/events` validates the envelope and stores raw JSON plus a tool-name/event-name search projection in D1. `GET /api/events?q=<session-id-or-tool>` and stateless MCP `search_traces` return recent matching records (100 maximum). Repeating an event ID for the same owner is idempotent; the first payload wins. The remote MCP endpoint is `POST /mcp` **on the API Worker URL**, not the Website URL.

All private routes reject requests without a Cloudflare Access identity, including direct workers.dev access. The single-tenant Access application permits the configured owner's email and, optionally, an explicitly provisioned Access service token. The API Worker is enrolled with Access and advertises managed OAuth with dynamic client registration for browser-based MCP clients. A hook is noninteractive: give it only a dedicated Access service token (ID + secret) via its local environment, never a browser session or a secret in a repository. The hook bridge fails open from the agent's perspective; delivery is best effort. No payload contents or credentials are logged intentionally. The Website is a public information page; its service-binding `/api/*` forwarding does **not** establish Access identity, so private API calls should use the API Worker URL directly.

Before any deployment, set `TRACES_ACCESS_EMAIL` to the account allowed to inspect traces. Without it, the Access policy matches an invalid placeholder email and intentionally admits nobody. Provision a Cloudflare Access service token and pass its **token ID** as `TRACES_ACCESS_SERVICE_TOKEN_ID` during the Alchemy plan if noninteractive submissions are wanted; this is a policy change requiring explicit approval. Keep the token _secret_ only on the local agent machine as `CF_ACCESS_CLIENT_SECRET`. `TRACES_ENDPOINT` is the API Worker base URL and `CF_ACCESS_CLIENT_ID` is the Access client ID. Set those three environment variables outside source control and run `bun scripts/submit-hook.ts claude-code` (or `codex`) as a command hook. Run a new agent session after editing hook settings. This is an opt-in bridge, not a production installer.

## Integration plan

| Agent                                                                                         | Capture mechanism                                                                                  | Initial support                                                                   |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| [Pi](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md) | Trusted extension under `.pi/extensions` or `~/.pi/agent/extensions`; lifecycle and tool events.   | Schema accepts pi; extension not yet shipped.                                     |
| [Claude Code](https://docs.claude.com/en/docs/claude-code/hooks)                              | Command hooks in `.claude/settings.json` or `~/.claude/settings.json`; JSON stdin.                 | Opt-in bridge for session/prompt/tool/stop events, subject to tested hook config. |
| [Codex](https://github.com/openai/codex/blob/main/codex-rs/config/src/hook_config.rs)         | `.codex/hooks.json` or `~/.codex/hooks.json` command hooks; legacy `notify` is turn-complete only. | Opt-in bridge for hook events; confirm active CLI version before installation.    |
| Amp                                                                                           | MCP tools exist; a stable turn/tool lifecycle hook API was not verified.                           | MCP search only. Do not infer traces of Amp activity from MCP calls.              |

`inspect_hooks` exposes these locations and limitations as MCP guidance. A remote server cannot inspect or edit a caller's filesystem on its own. A future installer must run in the agent's local context, read and merge existing hook config (never overwrite), show the exact diff, request user approval, write atomically, and verify a test event. It must avoid printing or embedding secrets. Do not claim the current read-only tool has installed hooks.

## Storage and risk

D1 is the interactive session index and raw event store for this first slice. Search is by exact session ID or escaped substring of projected tool/event names; this is deliberately **not** full-text search across raw payloads. Source-specific mapping currently extracts `tool_name` or `toolName`, falling back to the event name; the complete source JSON remains in `raw` for later reinterpretation. Other agent event shapes need sample fixtures before richer mapping. D1 row size, write throughput, retention/deletion, secret redaction, pagination, tenant separation, and Access OAuth client interoperability need evaluation before real traces containing sensitive prompts are accepted.

[Cloudflare Basin/Pipelines](https://developers.cloudflare.com/basin/) is GA and supports Worker/HTTP stream ingestion into Iceberg and SQL query. Ingestion-to-query can take minutes, so it is an **analytics/archive candidate**, not the interactive index. Evaluate pricing, size limits and propagation latency against production volume before adding a fan-out. No Basin resources or paid deployment have been created.
